### Day 5. Ledgers (onboarding Step 4)

One Google Sheet per matter, used as a ledger you keep true from evidence: **Work** (commitments), **Hours** (time) and **Change log** (every write). The morning briefing reads from these sheets. Your nightly pass proposes and the owner says "apply". That stays the default until the owner changes it for a specific matter.

Matter Ledger template (view only): https://docs.google.com/spreadsheets/d/15ikRHneBDL3v1ixltMG_GHxNI9km0WicvIKZMnRVIBg. Copy link: https://docs.google.com/spreadsheets/d/15ikRHneBDL3v1ixltMG_GHxNI9km0WicvIKZMnRVIBg/copy

Read `matters.md` and `sources.md` first. If either is missing, say so and work from what the owner tells you.

1. **One ledger per matter, first-wave matters first.** Use a copy link the owner sent if there is one. Otherwise copy the template yourself if your Drive tools allow it, or ask them to open the copy link once per matter and send you each new link. Never rebuild the Google Sheet by hand, because the dropdowns, formulas and formatting matter. For a markdown ledger, record the file name. If they only start with the first-wave matters, list the rest as "later". Tell them once: by Day 7, every active matter needs a live ledger or moves to the Later line in `matters.md`, and Day 7 checks this.
2. **Tailor each copy (setup only, the only structural change you ever make).** Replace `[CODE]` and `[Matter name]` in A1 of Hours, Work and Change log. Sub-area dropdowns (Hours and Work): the matter's sub-areas plus "General" and "To confirm". Hours > Status: leave it at `accepted`, `pending` (the headline counts WORKED and PENDING from these, so add nothing). Work > Owner: "Me", the roles that own things, "Other party", "To confirm" (roles, not names). Don't rename tabs, move columns or touch rows 2–4 beyond the A1 title. Log each change in the Change log with action `setup`. Read back the headers and dropdowns and send the link. Expected row-4 headers:
   - **Hours:** Date · Type · Hours · Sub-area · Description · Work ID(s) · Status · Source / evidence · Notes (dropdowns on Type, Sub-area and Status; Hours accepts only positive quarter hours)
   - **Work:** ID · Commitment · Owner · Status · Target · Waiting on · Next step · Notes · Sub-area (dropdowns on Owner, Status and Sub-area)

3. **Header map. On scheduled runs, `Source / evidence` starts with `auto YYYY-MM-DD`. Change log: one row per write. Rows 1–3 are the frame, row 4 is the header, data starts at row 5 and new rows go at the top. If a header is missing or renamed, stop and tell them.
   Write `ledgers.md` with one block per matter: `## [CODE] · [name]`, Sheet, Sheet ID, Track hours, Type list, Sub-areas, Owners, `Sources: see sources.md#[CODE]`, Teammate bot, `Nightly mode: propose`, Status live/later. Nightly mode is propose for every matter unless ledgers.md says otherwise."
4. **Tracker skills.** Confirm work-tracker, hours-tracker and tracker-dry-run are present and attach them to each live ledger. If one is missing, report it and don't write a replacement. 5. **Dry-run backfill (writes nothing).** Run the last 14 days for the first-wave matters. 7. **Nightly tracker pass**, every day at [22:30] in the owner's time zone. Read it back and test it. The owner decides, and you may suggest it with evidence on Day 7 or later. **Never** overwrite manual edits (a human edit wins), delete rows, clear ranges, change structure, send, reply, pay or invite. Message the owner immediately only if a sheet is unreachable, auth was lost, or data may be corrupted.
